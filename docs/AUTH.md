# 로그인 · 계정 · 온보딩 설계 (PvP 단계에서 구현)

> **상태: 설계 문서. 1.0(싱글+토큰)에는 로그인이 없다 — 구현하지 말 것.**
> 개인정보를 수집하지 않는 현재 상태가 심사·정책상 가장 단순하다.
> 이 문서는 PvP(`PVP_SERVER.md`)를 만들 때 함께 구현한다.

## 0. 확정 원칙

| 항목 | 결정 | 이유 |
|---|---|---|
| 게스트 우선 | **로그인 없이 싱글은 전부 플레이 가능.** 로그인은 PvP·랭킹 동기화·서버 지갑에만 요구 | 심사 통과 쉬움, 이탈 최소화. "로그인 장벽" 없는 지금 UX를 지킨다 |
| 인증 제공자 | **Firebase Auth** (Google + Apple) | 무료(Spark), 두 로그인 다 지원, 토큰 검증 라이브러리 성숙 |
| ⚠️ Apple 의무 | 구글 로그인을 넣는 순간 **Sign in with Apple도 필수** (App Store 심사 규정 4.8) | iOS 출시 계획이 있으므로 처음부터 둘 다 구현 |
| 서버 | 인증은 Firebase, **게임 서버는 기존 설계대로 Cloud Run + Neon** | 서버는 Firebase ID 토큰 서명만 검증하면 된다 — 세션 저장소 불필요, 무료 유지 |
| 익명 → 연동 | 게스트의 로컬 기록(RP·전적)은 **첫 로그인 때 서버로 이관**하고 로컬은 유지 | "로그인했더니 전적이 날아갔다"는 최악의 첫인상 방지 |

## 1. 화면 흐름

```
[PvP 버튼] ──로그인 안 됨──▶ [로그인 시트: Google / Apple]
                                    │ Firebase 로그인 성공
                                    ▼
                          서버 GET /me (ID 토큰 첨부)
                          ├─ 200 계정 있음 ──▶ 바로 매칭 화면
                          └─ 404 첫 방문 ──▶ [온보딩]
                                             1) 만 14세 이상 확인 (필수 체크)
                                             2) 개인정보 수집·이용 동의 (필수 체크, 정책 전문 링크)
                                             3) 닉네임 입력 + 서버 검증
                                             ▼
                                       POST /signup → 계정 생성 + 로컬 기록 이관
```

- 동의 없이는 계정을 만들지 않는다. 게스트로 돌아가기 버튼을 항상 둔다.
- 동의 기록은 **버전과 시각을 서버에 저장**한다(`consent_version`, `consented_at`) —
  나중에 정책이 바뀌면 어떤 버전에 동의했는지가 근거가 된다.
- 만 14세 미만: 한국 개인정보보호법상 법정대리인 동의가 필요 → 받지 않는 것으로 회피.
  "만 14세 이상입니다" 확인을 필수로 하고, 아니면 계정 생성 불가(게스트 플레이는 가능).

## 2. 닉네임 규칙 (서버에서 강제 — 클라 검증은 UX용일 뿐)

| 규칙 | 값 |
|---|---|
| 길이 | 2~12자 (한글·영문·숫자, 공백/특수문자 불가) |
| 고유성 | **전역 유니크 아님** — 내부는 `id`가 식별자, 표시는 `닉네임#1234` (임의 태그) |
| 금칙어 | 서버 필터(욕설·운영 사칭). 목록은 서버에만 두고 갱신 가능하게 |
| 변경 | 가능(쿨다운 30일). 랭킹 어뷰징 방지 |

태그 방식을 쓰는 이유: 유니크 강제는 선점 문제(좋은 이름 고갈)와 중복 검사 UX가 나쁘다.
Discord식 태그면 충돌 걱정 없이 첫 온보딩이 한 번에 끝난다.

## 3. DB 스키마 (Neon)

```sql
CREATE TABLE users (
  id            BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  firebase_uid  TEXT UNIQUE NOT NULL,          -- 인증 식별자 (Google/Apple 공통)
  nickname      TEXT NOT NULL,
  tag           SMALLINT NOT NULL,             -- 닉네임#0000
  consent_version TEXT NOT NULL,               -- 동의한 정책 버전 (예: '2026-08-20')
  consented_at  TIMESTAMPTZ NOT NULL,
  age14_confirmed BOOLEAN NOT NULL,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at    TIMESTAMPTZ                    -- 소프트 삭제(30일 후 완전 파기 배치)
);
-- 서버 지갑·랭킹은 PVP_SERVER.md의 테이블에 user_id FK로 연결
```

수집을 **최소로 유지한다**: 이메일·프로필 사진은 받지 않는다(Firebase 스코프 최소 요청).
저장하는 개인정보는 사실상 `firebase_uid` + 닉네임뿐 — 정책 문서도 그만큼만 커진다.

## 4. 서버 인증 (Cloud Run)

- 클라는 모든 요청(WebSocket 핸드셰이크 포함)에 **Firebase ID 토큰**을 첨부.
- 서버는 Google 공개키로 서명 검증(라이브러리 캐싱, 네트워크 왕복 없음) → `firebase_uid` 확보.
- 자체 세션/JWT 발급 없음 — 상태 저장이 없어야 Cloud Run 무료 티어에 맞는다.

## 5. 계정 삭제 (양 스토어 심사 필수)

- **인앱**: 설정 → 계정 삭제 → 재확인 → `DELETE /me` (소프트 삭제, 30일 후 파기).
  서버 지갑 잔량도 함께 소멸됨을 고지하고 동의받는다.
- **웹**: 앱 없이도 삭제 요청 가능한 경로 필요(Google Play 정책) →
  정책 페이지에 삭제 안내 섹션 추가(메일 요청 처리).
